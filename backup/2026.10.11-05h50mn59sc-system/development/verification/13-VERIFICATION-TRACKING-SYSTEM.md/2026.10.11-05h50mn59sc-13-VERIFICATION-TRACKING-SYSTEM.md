# M. Verification Tracking System

## Primary entity fields

Each verification entity/pathway should retain, when applicable:
- ID, name, category, subcategory, website/source.
- scope, methodology, standards, evidence requirements, outputs.
- credibility basis, limitations, manipulation resistance.
- NOVA replicability, replication complexity, replication equivalence.
- cost model and verified cost range.
- ecosystem importance and AstroCrown relevance.
- necessity status, context and trigger conditions.
- current/future feasibility and blocking requirements.
- earliest practical stage, typical stage, latest useful stage, stage independence.
- opportunity-readiness state, required documents/systems, missing preparation and unpreparedness cost.
- discovery/search/social/ecosystem/institutional visibility.
- credibility/trust/adoption/operability impacts.
- independence, evidence state, operational status, open questions, provenance and review dates.

## Operational statuses
- Not Investigated
- Researching
- Candidate
- Planned
- In Progress
- Submitted
- Passed
- Failed
- Expired
- Superseded
- Blocked

These are lifecycle states, not quality scores.

## Evidence states
- VERIFIED
- DERIVED
- CANDIDATE
- UNKNOWN
- BLOCKED

Evidence state and operational status are independent.

## Verification cycle

Discover → Identify → Source/provenance → Classify → Extract methodology → Identify evidence requirements → Assess NOVA replication → Assess AstroCrown gaps → Assess readiness → Monitor trigger → Prepare → Execute external verification → Record result/evidence → Monitor expiry/scope changes → Re-verify.

## Closure rule

A failed verification is not closed by changing code alone. Re-run the original verification, perform relevant regression checks, retain new evidence and close only when the evidence supports closure.
