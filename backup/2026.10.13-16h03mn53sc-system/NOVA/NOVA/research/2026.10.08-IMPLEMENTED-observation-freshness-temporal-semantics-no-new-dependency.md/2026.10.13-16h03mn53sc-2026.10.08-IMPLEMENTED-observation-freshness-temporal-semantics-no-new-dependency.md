# NOVA observation freshness — implemented

Date: 2026-10-08
Status: IMPLEMENTED

## Purpose

Prevent the system from silently treating an old observation as if it were a current description of reality.

## Implemented

- Added explicit observation timestamp parsing.
- Added temporal freshness classification: FRESH, STALE, UNSPECIFIED, and invalid-time/policy states.
- Added optional freshness policy to stored external observations.
- Reusable external analysis is rejected when its underlying observation is stale.
- Provider health can now be evaluated against an explicit maximum observation age.
- AI heartbeat fallback routing uses the configured six-hour observation-age boundary and deprioritizes stale provider evidence.
- Added unit tests for observation freshness, stale analysis reuse, stale provider health, and stale routing.
- Added a dedicated validation workflow for NOVA changes.

## Semantic rule

A stale observation is not evidence that the underlying state is false. It means NOVA has not freshly observed the subject within the declared observation window.

The system therefore distinguishes evidence freshness from truth.

## Dependency status

No new external GPU, AI provider, or scientific-computing dependency was required for this implementation.

The advanced nonlinear interaction work remains intentionally unimplemented and is recorded separately under a filename that exposes its dependencies.
