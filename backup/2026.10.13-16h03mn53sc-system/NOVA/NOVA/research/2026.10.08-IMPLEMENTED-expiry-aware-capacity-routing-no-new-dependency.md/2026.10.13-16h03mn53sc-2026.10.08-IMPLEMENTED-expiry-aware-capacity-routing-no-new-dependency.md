# NOVA expiry-aware resource allocation — implemented

Date: 2026-10-08
Status: IMPLEMENTED

## Purpose

Use provider-exposed capacity windows dynamically instead of waiting for a fixed routing interval when usable resources are approaching reset or expiration.

## Implemented

- Capacity observations can now produce an explicit opportunity signal.
- A resource window can be marked EXPIRING_SOON when usable capacity has a known upcoming reset or expiration within the configured urgency window.
- Protected remaining capacity is not consumed merely because a window is expiring.
- Unknown or stale capacity observations receive no artificial scheduling boost.
- Runtime provider ordering now uses imminent capacity opportunity after health preference.
- The heartbeat remains a live probe and is not replaced by expiry-driven scheduling.

## Current default policy

- Urgency window: 300 seconds.
- Protected remaining reserve: 20 percent when a limit is known.
- Maximum age for capacity used for expiry-aware routing: 900 seconds.

## Important semantic boundary

A reset/expiration deadline is an observed scheduling constraint, not proof that a provider will behave exactly as predicted. The scheduler therefore optimizes against observed capacity without treating the observation as reality itself.

## Example

If Provider A has 80 of 100 requests remaining and the observed reset is five minutes away, while Provider B has no imminent capacity boundary, A can be preferred for eligible runtime work before its currently observed window closes.

## Future extension

Task-level resource estimates should eventually be considered so NOVA can decide whether a specific request fits the expiring capacity without wasting scarce capacity or triggering an avoidable fallback.

Dependency for that extension: TASK-RESOURCE-ESTIMATION-BENCHMARK.

## Economic and renewal guard

Expiry pressure is not sufficient to increase scheduling priority.

An expiring resource may be rapidly renewable, slowly renewable, paid, free, or economically unknown. NOVA now supports explicit renewal metadata and an economic signal.

Rules:

- Never create work only to consume an expiring allocation.
- Expiry can improve priority only for work that is already required and has a non-negative observed economic case.
- Paid capacity requires task benefit/cost information before expiry can justify prioritization.
- Free capacity can be treated as non-negative only when explicitly identified as free; it remains subject to the rule that it must serve required work.
- Unknown economics never receive an expiry boost.
- Renewal frequency is treated as a separate dimension from expiry; a rapidly renewing quota is not automatically economically scarce.
- Protected reserves remain in force.
- The allocator does not infer provider pricing or renewal behavior from missing fields.
## Resource balance versus call allowance

NOVA now distinguishes total resource observations from call/window allowances.

A request-per-second, request-per-minute, token-per-minute, concurrency, or similar allowance describes an operational consumption constraint for a call or window. It must not be used as evidence of the provider's total resource balance.

Total resources such as credits, neurons, GPU seconds, GPU hours, storage, or bandwidth must be supplied as explicit resource observations when available.

This distinction is necessary for expiry-aware allocation: a short allowance window may renew rapidly without representing scarce total capacity, while a large total balance may still be constrained by small per-call allowances.

## Task-level allocation substrate implemented

NOVA now has a deterministic allocator that can evaluate a proposed task against multiple resource/provider candidates without making a live provider call.

The allocator keeps hard constraints separate from optimization signals: health validity, call allowance fit, and total resource fit are checked independently. Known economic value, expiry opportunity, quality, latency, and negative effects are optimization dimensions when the required measurements exist.

Candidate selection uses a Pareto frontier rather than a universal weighted score. This avoids inventing a conversion between incomparable units such as dollars, milliseconds, tokens, reliability, and resource scarcity.

Unknown values do not create positive priority.
