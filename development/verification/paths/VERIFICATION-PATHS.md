# L. Verification Paths

## Path model
Entity/pathway → trigger → prerequisites → evidence package → execution → result → publication/evidence retention → expiry/change detection → re-verification.

## Core paths
### Security
Internal SSDF/ASVS mapping → threat model → automated/manual testing → independent audit where warranted → remediation → re-test → public evidence as appropriate.

### Formal verification
Define properties/invariants → map source/bytecode → specify assumptions → prove/test → retain proof artifacts → re-run after relevant contract changes.

### Bug bounty
Define attack surface → exclusions → severity model → response SLA → budget/rewards → disclosure/triage → remediation → closure/re-test.

### Exchange readiness
Legal/compliance dossier → token/contract facts → security evidence → tokenomics/treasury evidence → market/community evidence → venue-specific submission → preserve outcome and changed criteria.

### Regulatory
Determine activity/jurisdiction facts → map applicable perimeter → identify entity obligations → prepare controls/disclosures → seek jurisdiction-specific advice/authorization where required → monitor changes.

### Research
Research question → reproducible dataset/code → methodology/provenance → independent review/publication pathway → preserve revisions and peer-review outcomes.

### Reserve assurance
Reserve definition → custody/reconciliation architecture → circulation/source data → independent assurance → recurring publication/reconciliation → exception handling.

### Media
Verified fact pack → primary evidence/source list → conflict/disclosure information → editorial outreach → preserve published result and corrections.

## Principle
Stage is secondary to trigger. A pathway can become useful earlier or later than a conventional lifecycle model suggests.
