# Discovery Register

This register indexes cross-cutting discoveries that materially affect AstroCrown Web development beyond a single UI implementation detail.

Homepage-specific discovery IDs remain authoritative in `development/HOMEPAGE-REQUIREMENTS.md`. Entries below preserve the broader reusable implications.

## D-015–D-024 — External data, law, and synthesis

### D-015 — External-source capability is not equivalent to provider ownership
A higher-level information system can potentially synthesize multiple lawful external observations without reproducing every provider's underlying infrastructure.

### D-016 — Legal right, provider permission, contract, and technical access are separate dimensions
Provider terms, policy, contract, statutory rights/exceptions, and technical accessibility must not be silently substituted for each other.

### D-017 — Educational purpose is relevant but not self-executing
Educational purpose can materially affect legal analysis but is not a universal authorization.

### D-018 — Public visibility, machine access, and reuse must not be conflated
Publicly visible information may have a restricted API or downstream-use conditions, while technical API access may still have licensing or contractual constraints.

### D-019 — Multi-source synthesis changes the competitive benchmark
The meaningful future comparison is the quality of AstroCrown's multi-source result for a defined user question versus each relevant individual-source result.

### D-020 — Source diversity requires upstream-independence analysis
Different brands may depend on the same upstream observation and therefore should not automatically count as independent evidence.

### D-021 — Provider restrictions should often trigger source-substitution research
A provider-specific restriction may require another lawful source rather than abandonment of the information objective.

### D-022 — Legal status should be represented as a state, not a Boolean
Use multi-dimensional status because purpose, jurisdiction, access method, contract, retention, redistribution, and transformation can matter.

### D-023 — External-source research is reusable capability
Source access, provenance, cost, update cadence, restrictions, and fallbacks can support the homepage, analytics, research, and NOVA.

### D-024 — Source restrictions and legal rights must remain historically traceable
Changing provider policy, pricing, API limits, or legal circumstances should generate a new verified state rather than silently rewriting history.

## D-025–D-033 — Acquisition paths and access controls

### D-025 — Acquisition method is independent from source availability
An unavailable or restricted API does not by itself prove that the underlying information is unavailable through another channel.

### D-026 — Non-API retrieval can expand the source universe
Public files, feeds, archives, filings, web tables, blockchain data, and other channels can provide useful information without a conventional API.

### D-027 — Alternate technical channels must not become a circumvention assumption
A change from API to page retrieval or another route may remain restricted by technical controls, provider terms, contract, or law.

### D-028 — Research-tool failure is not evidence of source unavailability
A browsing/tool environment may fail to retrieve information that remains available to the intended application runtime.

### D-029 — Static and downloadable data can improve operational resilience
Static sources can reduce API-key dependence, lower request frequency, improve reproducibility, support historical backfill, and provide stable snapshots.

### D-030 — $0 is a multidimensional operational objective
Free provider access, free automation, free commercial use, free infrastructure, free prototype operation, and free production scale are different states.

### D-031 — Site interdiction, technical blocking, and legal prohibition are distinct findings
Provider statements, robots.txt, CAPTCHA, WAF, HTTP blocks, rate limits and similar mechanisms are access observations, not automatically legal conclusions.

### D-032 — Anti-automation controls can make access more restrictive than the legal information question
A lawful information objective can still be operationally infeasible through a particular provider channel.

### D-033 — Access-control observation needs provenance
Observed technical behavior should preserve channel, environment, timestamp, response state, and supporting evidence.
